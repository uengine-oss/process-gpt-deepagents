# 주가·지수 조회

시세는 네이버 증권의 공개 JSON 에서 샌드박스(`execute`)로 직접 읽는다. 키는 필요 없고
요청 헤더 `User-Agent: Mozilla/5.0` 만 넣는다. 주소·응답 필드·예시 코드는
`references/naver-finance-api.md` 에 있다 — 처음 조회하기 전에 읽는다.

## 1. 이름 → 종목 찾기

사람이 말한 이름을 그대로 믿고 코드를 짐작하지 않는다. 언제나 종목 검색(자동완성)으로 찾는다.

1. 말한 이름 그대로 검색한다. 국내·해외 종목과 지수가 한 번에 나온다(`target=stock,index`).
2. 안 나오거나 맞는 것이 없으면 **표기를 바꿔 다시** 찾는다: 띄어쓰기 넣기·빼기, 영문 이름,
   한글 음차, 약칭, 정식 회사명, 티커. 앞 단어 하나만으로도 찾아 본다. 국내·해외 둘 다 본다.
3. 후보를 고를 때 본다: `category`(stock / index), `typeCode`(KOSPI·KOSDAQ·NASDAQ·NYSE·TOKYO·INDEX·
   WORLD_INDEX …), `nationCode`. 지수를 물었는데 같은 이름의 회사 종목이 먼저 나올 수 있다
   (`category` 가 index 인 것을 고른다). ETF 와 원주·ADR 이 같이 나오면 말한 시장과 맞는 것.
4. 사람이 코드나 티커를 직접 적었으면 그 코드로 검색해 이름이 맞는지만 확인한다.
   예약 작업의 지시문에 괄호로 코드가 붙어 있어도, 그 코드의 종목 이름이 사람이 말한 이름과
   다르면 **이름 쪽을 믿고 다시 찾는다**(지시문을 쓴 쪽이 코드를 짐작했을 수 있다).
5. 그래도 못 찾으면 **코드를 지어내지 않는다.** 시도한 검색어와 가까운 후보(이름·시장·코드)를
   적고 "찾지 못했다"고 쓴다. 후보가 둘 이상으로 갈리고 대화 중이면 어느 것인지 묻는다.
   예약 실행처럼 물을 사람이 없으면 가장 맞는 것을 고르고 고른 근거를 결과에 밝힌다.

## 2. 값 읽기

- **지금 가격**: 종목·지수의 기본 정보(`…/basic`). `marketStatus` 가 `OPEN` 이면 장중 값,
  `CLOSE` 면 마지막 거래일 종가다. 기준 시각은 `localTradedAt`(그 시장의 시간대).
- **날짜별 종가**: 일봉(`…/day`). 거래일만 오래된 날부터 온다. 주봉·월봉도 같은 꼴이다.
- 국내 종목·국내 지수·해외 종목·해외 지수는 주소가 다르다(references 표).

## 3. 기간 계산

- 「N거래일 누적 등락률」 = (가장 최근 종가 ÷ 그 N거래일 전 종가 − 1) × 100.
  일봉 배열에서 마지막 원소와 끝에서 N+1 번째 원소다. 휴장일은 배열에 없으니 날짜로 빼지 않는다.
- 기간을 넉넉히 받는다(N거래일이면 달력으로 2N+10일). 받은 행 수가 N+1 보다 적으면 그렇다고 쓴다.
- 「N일」이라고만 했으면 거래일로 계산하고 그렇게 했다고 밝힌다. 「N주」「한 달」은 달력 기간의
  첫 거래일 종가와 비교한다.
- 장중이면 일봉의 마지막 행이 진행 중인 값일 수 있다. 「지금 기준」이 필요하면 `basic` 의 현재가를
  최근 값으로 쓰고 그렇게 했다고 적는다.
- 조건(예: 누적 ±5% 이상)을 판정할 때는 계산한 값과 기준을 함께 적는다.

## 4. 답에 적을 것

- 고른 종목: 이름 · 시장 · 코드(해외는 reutersCode), 그리고 기준 날짜(시간대).
- 값과 통화(원·달러·엔), 계산에 쓴 두 종가와 날짜.
- 맨 끝 한 줄: `출처: 네이버 증권(<읽은 주소>)`.
- 못 읽은 종목이 있으면 숨기지 않고 무엇이 실패했는지(검색 결과 없음, 응답 오류 코드) 적는다.
  값을 추정해 채우지 않는다.

## 실패할 때

- 일봉이 빈 배열(`[]`)이거나 기본 정보가 409(`StockConflict`)면 코드가 틀린 것이다 → 1절로 돌아가 다시 찾는다.
- 연결 실패·5xx 는 한 번 다시 시도한다. 그래도 안 되면 실패한 주소와 상태를 적고 멈춘다.
- 네이버 증권에 없는 시장·상품(암호화폐 등)은 다른 출처를 지어내지 말고 없다고 쓴다.
